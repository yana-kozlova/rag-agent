# Telegram

**One reply, two surfaces, and only one renders Markdown.** `sendMessage` (`lib/telegram/api.ts`) sends without `parse_mode` deliberately — MarkdownV2 requires a dozen characters escaped everywhere and rejects the whole message when one is missed, so an unstyled message that always arrives beats a styled one that intermittently 400s. The consequence went unhandled for as long: every `**` and `###` the model wrote reached the bot as literal punctuation, so a schedule arrived as `### Завтра` over `1. **Робочі години**`, noisier than the plain text it was decorating, while the web chat rendered the same reply properly. `stripMarkdown` removes the syntax rather than translating it, running after `flattenMarkdownLinks` because that one rewrites the bracket form this leaves alone. Emphasis is unwrapped only where the marks hug the text, so `3 * 4 * 5` survives; list markers stay, because in plain text a list still reads as one. Schedule layout is then a prompt rule rather than an assembled block — `getEvents` answers "чи вільна я о 15?" as much as "що цього тижня?", and only the second wants a list — but the pieces the rule needs are supplied, not computed by the model: `Day` and `At` are in the line ready to print.

**One bot serves many people, and only in private chats.** The binding is a per-user column (`users.telegram_chat_id`, unique), so every account that can sign in can link its own chat to the same bot; `findUserByChatId` resolves the owner per update and `runWithUser` scopes the agent to them. The gate on all of it is `ALLOWED_EMAILS`, since a code can only be issued from an authenticated session. That same design is why group and channel updates are dropped (`isPrivateChat` in `lib/telegram/process.ts`): a chat id is the entire identity here — nothing asks *which* member is speaking — so a linked group would hand every current and future member the owner's knowledge base and calendar. `/unlink` lives on the bot side rather than only in settings, because someone who was invited to this instance may never open the web app again and still needs to stop the bot answering as them. For the same reason user-facing failures never name an env var: whoever is typing may be a guest on someone else's deployment, so the setting goes to the log and the chat gets "write to me in text instead".

Photos and documents (`lib/telegram/media.ts`) are **saved, not discussed**: they arrive with no question attached, so `processUpdate` ends the turn on them rather than feeding a wall of OCR to the agent and burning its step budget. The reply quotes back what was actually read, because vision output is the one thing here the user cannot verify against a source — a misread figure on a receipt has to be caught while the paper is still in hand. A caption becomes the title. Telegram re-encodes photos to JPEG, so HEIC never reaches this path; images sent *as documents* (what you do when compression would make a page of text unreadable) are detected and routed to the image path rather than rejected.

`/q` prints the quick-action buttons (`lib/telegram/quick-actions.ts`) — a command rather than a persistent reply keyboard, which would otherwise sit under every message including the ones asking a question. This is where the feature earns most of its keep: the routines it records happen with a phone in hand and nowhere near a browser. Unlike a notification's keyboard, a pressed quick-action panel keeps its buttons — it is a control panel, not a one-time decision, and tomorrow's press should not need a new `/q`. A reply to a `force_reply` prompt is intercepted before the agent runs, because "37.2" sent to the model comes back as a polite enquiry about what that means.

`/google` is the fourth command beside `/start`, `/unlink` and `/q`, and the only one that exists to repair something: it checks whether Google still honours the stored permission and, when it does not, hands over the numbered steps and a link to Settings → Google. See "A refresh token is not forever" under Request context — the reasoning is there because three surfaces share it.
